# База AniShiki

`00_anishiki_schema.sql` — вся схема аккаунта сайта: таблицы, индексы, RLS и
бакет аватаров. Файл снят с боевой базы и применим на чистом проекте целиком.

## Переезд на отдельный проект

Сейчас таблицы AniShiki делят проект Supabase с базой VPN-бота
(`users`, `subscriptions`, `payments`, …). Разделение упирается в лимит
бесплатного тарифа: два активных бесплатных проекта на владельца. Чтобы
освободить слот, нужно в дашборде Supabase удалить или поставить на паузу
лишний проект, либо перевести организацию на платный план.

Когда слот освободится, порядок такой:

1. Создать проект `anishiki` (регион eu-central-1 — ближе к пользователям,
   чем текущий eu-west-1).
2. Применить `00_anishiki_schema.sql`.
3. Перенести пользователей: строки `auth.users` вместе с `encrypted_password`
   переносятся как есть, пароли остаются рабочими (bcrypt).
4. Перелить данные таблиц: `profiles`, `favorites`, `lists`, `ratings`,
   `history`, `friendships`, `comments`, `activity`. Объём небольшой.
5. Переключить приложение: `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`
   в переменных окружения Vercel (значения по умолчанию лежат в
   `src/lib/supabase.js`).
6. Проверить вход, историю и загрузку аватара — и только потом удалять
   таблицы AniShiki из проекта VPN-бота.

Таблицы VPN-бота в этих миграциях не участвуют и не изменяются.
