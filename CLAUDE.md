# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Язык

Проект русскоязычный. Комментарии в коде, сообщения коммитов и текст интерфейса — по-русски.
Комментарий объясняет **почему** так сделано (обычно — какая ошибка была раньше), а не пересказывает код.

## Команды

```bash
npm run dev      # Vite dev-сервер, http://localhost:5173
npm run build    # статическая сборка в ./build
npm run preview  # прогон собранного
npm run check    # svelte-kit sync && svelte-check
```

Тестов в проекте нет — ни фреймворка, ни файлов. Проверка правки: `npm run build`,
`npm run check` и открыть страницу в браузере.

`npm run check` даёт **5 давних ошибок** в `src/routes/player/[id]` и `src/routes/c/[id]`
(вендорные `webkit*`-API, которых нет в типах DOM). Это фон: сверяйтесь с числом, а не
с фактом наличия ошибок.

## Что это за приложение

Неофициальный веб-клиент Anixart. `adapter-static` + `ssr = false` (`src/routes/+layout.js`) —
чистая SPA, всё выполняется в браузере, сервера у приложения нет. Единственный серверный
кусок — Vercel-функции в `api/`: `kodik.js` распаковывает Kodik, а `source.js` получает
прямые потоки известных внешних плееров. В dev их подменяет middleware из `vite.config.js`.

Данные идут из браузера напрямую в API Anixart. При CORS-ограничениях сервер меняется в
Настройках (`api.anixart.app` ↔ `api-s.anixsekai.com`), в dev есть прокси `/anixart-proxy`.

## Два вида аккаунта — главное архитектурное решение

В приложении **два независимых аккаунта**, и они обязаны быть равны по возможностям:

| | Аккаунт Anixart | Аккаунт AniShiki |
|---|---|---|
| Хранилище | API Anixart (`anixartjs`) | Supabase (`@supabase/supabase-js`) |
| Вход | `userToken` в localStorage | сессия Supabase |
| Идентификатор | число | uuid |
| Профиль | `/profile/[id]` | `/u/[id]` |
| Слой данных | `src/lib/api.js` | `sitedata.js`, `siteprofile.js`, `friends.js`, `collections.js`, `notifications.js` |

Экран профиля у обоих **один** — `src/lib/components/ProfileView.svelte`. Страницы только
приводят свои данные к общей форме (объект `p`) и передают кнопки действий слотом.
Так сделано намеренно: пока отрисовка общая, разойтись по возможностям аккаунты не могут.
**Добавляя блок в профиль, добавляйте его в `ProfileView`, а не в одну из страниц.**

Пользователь может быть залогинен в оба сразу. Отсюда правило: страницы `/bookmarks`,
`/history`, `/friends` переключаются на данные сайта только при `!$userToken && $siteSession`,
поэтому из профиля сайта ссылки ведут в разделы `/u/[id]/...`, а не на общие страницы.

`/me` — переадресация на `/u/<свой id>`. `/profile/<uuid>` — переадресация на `/u/<uuid>`
(`isSiteId()` из `siteprofile.js`).

## Supabase: приватность живёт в базе, а не в интерфейсе

RLS-политики — единственная настоящая граница. Белый список полей в `updateProfile()`
существует только в клиенте и ничего не защищает.

- `is_stats_hidden` реально закрывает `history`, `activity`, `lists`, `ratings`, `favorites`:
  чужую строку политика отдаёт, только если у владельца флаг снят. Своё видно всегда.
- `is_social_hidden` и `is_counts_hidden` — **только интерфейсные**: `profiles` читается всеми.
- `is_verified` / `is_sponsor` защищены триггером `protect_profile_flags` — пользователь не
  выдаст их себе, но и проставить их некому: админ-интерфейса нет.
- `history.watched_seconds` считает триггер `accumulate_watched_seconds`; клиент про колонку
  не знает и не должен её слать.
- Строку `profiles` создаёт триггер `on_auth_user_created`; `loadProfile()` в `stores/auth.js`
  дополнительно заводит её на месте, если не нашлась.

⚠️ `supabase/migrations/00_anishiki_schema.sql` — исходная схема. Последующие изменения
лежат отдельными файлами и применяются по порядку. В частности,
`202608300001_notifications_realtime_and_preferences.sql` добавляет подписки на события,
три режима приватности и включает `notifications` в Realtime publication. Без этой
миграции новый интерфейс бережно откатывается на старые переключатели, но режима
«только друзьям» и мгновенной доставки не будет.

## Гарантии, которые легко сломать

**Ключи в `{#each}`.** Дубли в выдаче API встречаются. Свалившийся ключ — не «ряд
отрисовался криво», а необработанная ошибка, после которой перестаёт обновляться весь
экран. `ReleaseRow`, `GridList` и оценки в `ProfileView` отбрасывают повторы; новый
keyed-блок делайте так же.

**Фильтр каталога.** Anixart игнорирует `genres`, если не прислать тело фильтра целиком.
Всегда через `buildFilter()` из `src/lib/filters.js`.

Метаданные релиза «Студия», «Страна» и «Год» ведут в `/search` с параметрами `studio`,
`country` и `year`. При добавлении нового фильтра синхронизируйте его в обоих направлениях:
`syncUrl()` и разбор параметров в `onMount()` поиска.

**Пагинация.** `total_page_count` приходит нулём — «есть ли ещё» определяется полнотой
страницы, а не этим полем.

**Голоса за комментарии.** `Like = 2`, `Dislike = 1` (не 1/-1). Сортировка комментариев:
`3` — популярные, `1` — новые, `2` — старые.

**`animation-fill-mode`.** В `.page-enter` именно `backwards`. С `both` у элемента навсегда
остаётся `transform`, он становится containing block для `position: fixed`, и модалки
уезжают за пределы экрана.

**IntersectionObserver.** Ненадёжен в некоторых окружениях — используйте `whenNear()` из
`src/lib/lazyload.js`, там есть запасной слушатель прокрутки.

**Service worker.** Кэш картинок только для чужих origin и `/_vercel/image` — свои иконки
туда попадать не должны, иначе обновлённая иконка не вылезет. Непрозрачный ответ отдаётся
только на `no-cors` запрос. Перезагрузка по `controllerchange` — под флагом `updateRequested`,
иначе страница перезагружает себя при первой же установке.

**iOS standalone.** `html, body { height: 100vh }` — именно `100vh`, а не `100%`: процентная
высота отключает `viewport-fit=cover`, и внизу появляется чёрная полоса. Метаданные PWA
фиксируются в момент «На экран Домой», поэтому изменения `apple-mobile-web-app-*` видны
только после переустановки ярлыка.

**Плеер.** API Anixart возвращает только ссылку на iframe эпизода и не отдаёт таймкоды
опенинга. Свой плеер сначала пробует прямой поток: Kodik через `api/kodik.js`, а AniLibria,
RuTube, VK, OK и Sibnet — через `api/source.js`. Если источник не поддержан или поток не
получен, остаётся режим «Оригинальный». В `api/_lib/source.mjs` жёсткий список доменов — не
ослабляйте его, иначе endpoint станет открытым прокси. Для AniLibria официальный API отдаёт
точные `opening.start/stop`; у остальных источников кнопка `OP` в нижней панели перематывает
вперёд на среднюю длину опенинга — 90 секунд. Всплывающая кнопка поверх видео показывается
на 12 секунд в начале точного опенинга либо в начале серии, если метаданных нет.

**Главная.** Hero и ряд «Популярные новинки» используют один фильтр: `sort: 3` и только
текущий год. Не расширяйте его прошлым годом: в таком случае популярные завершённые хиты
вытесняют действительно новые релизы.

**Совместный просмотр.** `src/lib/cowatch.js` использует один Supabase Realtime-канал на
комнату: presence для участников, broadcast для состояния и чата. Состояние по запросу и
каждые 20 секунд рассылает только хост — иначе гости перетирают друг друга. Когда хост уходит,
первый оставшийся участник становится им. Не убирайте проверку отправителя для `meta`: режим
«только хост управляет» должен меняться исключительно хостом. Интерфейс комнаты раскрывается
кнопкой в конце боковой панели плеера, а не показывается постоянно.

## Карта библиотек

```
src/lib/
  api.js          клиент anixartjs + слой совместимости для методов, которых нет в 0.1.x
  filters.js      тело фильтра каталога и наборы вариантов
  genres.js       группы жанров, канонизация названий
  search.js       умный поиск: транслитерация, релевантность, история
  catalog.js      кэш каталога (память + sessionStorage, stale-while-revalidate)
  picks.js        ряды подборок для главной и обзора
  lazyload.js     whenNear() — отложенная загрузка
  ios.js          определение iOS/standalone, haptic, свайп назад, оболочка
  pwa.js          установка, обновления, уведомления, бейдж
  utils.js        форматтеры, thumb() через оптимизатор картинок Vercel
  supabase.js     клиент Supabase (фичи сайта включаются только при наличии ключей)
  stores/
    index.js      persisted-сторы в localStorage: токен, тема, плеер, эндпоинт
    auth.js       сессия и профиль аккаунта сайта

api/
  kodik.js        серверное извлечение HLS Kodik
  source.js       серверное извлечение известных внешних плееров
  _lib/source.mjs whitelist провайдеров, AniLibria-метаданные опенинга
```

Компоненты, которые стоит переиспользовать, а не дублировать: `ProfileView`,
`ProfileSubPage` (оболочка разделов профиля), `ReleaseRow`, `GridList`, `Sheet`
(нижняя шторка iOS), `Donut`, `AreaChart`, `LazyRow`.

## Стиль кода

Svelte 5 в legacy-режиме: `export let`, `on:click`, `$:`. Runes в проекте не используются —
не смешивайте. Табы, одинарные кавычки, ширина 100.

## Деплой

Push в `main` → Vercel собирает и выкатывает. `vercel.json`: `outputDirectory: build`,
SPA-rewrite на `index.html`, оптимизатор картинок с белым списком хостов Anixart.
